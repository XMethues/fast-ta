# ta-wasm

## Responsibility
WebAssembly adapter for `ta-core` using `wasm-bindgen`. It exposes JS-friendly functions/classes and converts core errors into JS exceptions.

## Dependencies
- **wasm-bindgen**: export boundary for functions/classes and `JsValue` errors.
- **ta-core**: source of indicator logic, `Float`, `Indicator`, and `TalibError`.
- **console_error_panic_hook / web-sys**: optional browser-readable panic messages.
- **wasm-bindgen-test**: WASM/browser/Node test harness when JS behavior matters.

## Consumers
- **JavaScript/WebAssembly callers**: import exports generated by wasm-bindgen/wasm-pack.
- **Cargo workspace**: default member built by normal workspace builds.

## wasm-bindgen Export Boundary

```rust
use wasm_bindgen::prelude::*;
use ta_core::{overlap::SMA, Float, Indicator, TalibError};

fn core_error_to_js(err: TalibError) -> JsValue { JsValue::from_str(&err.to_string()) }

#[wasm_bindgen]
pub fn sma(prices: &[f64], period: usize) -> Result<Vec<f64>, JsValue> {
    if period == 0 { return Err(JsValue::from_str("period must be greater than zero")); }
    if prices.iter().any(|v| !v.is_finite()) { return Err(JsValue::from_str("prices must be finite")); }

    let core_prices: Vec<Float> = prices.iter().copied().map(|v| v as Float).collect();
    let output = SMA::new(period).compute_to_vec(&core_prices).map_err(core_error_to_js)?;
    Ok(output.into_iter().map(|v| v as f64).collect()) // preserve NaN warm-up
}
```

## Stateful Streaming Class Export

```rust
use wasm_bindgen::prelude::*;
use ta_core::{overlap::SMA, Float, Indicator};

#[wasm_bindgen(js_name = Sma)]
pub struct WasmSma { inner: SMA }

#[wasm_bindgen]
impl WasmSma {
    #[wasm_bindgen(constructor)]
    pub fn new(period: usize) -> Result<WasmSma, JsValue> {
        if period == 0 { return Err(JsValue::from_str("period must be greater than zero")); }
        Ok(WasmSma { inner: SMA::new(period) })
    }
    pub fn next(&mut self, price: f64) -> Result<f64, JsValue> {
        if !price.is_finite() { return Err(JsValue::from_str("price must be finite")); }
        Ok(self.inner.next(price as Float) as f64) // NaN means warm-up
    }
}
```

## WASM Initialization and Panic Hooks

```rust
use wasm_bindgen::prelude::*;

#[wasm_bindgen(start)]
pub fn start() {
    #[cfg(feature = "console_error_panic_hook")]
    console_error_panic_hook::set_once();
    web_sys::console::debug_1(&"ta-wasm initialized".into());
}
```

## Architectural Boundaries
- **NO core reimplementation**: call `ta-core` for indicators and numeric semantics.
- **NO Rust-only types in exports**: expose `f64`, `usize`, `String`, `Vec<f64>`, or `Result<T, JsValue>`.
- **NO WASM traps for user input**: validate before calling legacy assert-based core constructors.
- **NO assumption that panic hook is installed**: dependencies are configured, but code must call `set_once()`.

<important if="you are adding a new WASM export">
## Adding a New WASM Export
1. Pick stateless `#[wasm_bindgen] pub fn` or stateful `#[wasm_bindgen] pub struct`.
2. Validate JS inputs: period, finite numbers, and length requirements.
3. Convert `f64`/`&[f64]` into `ta_core::Float` values.
4. Call public `ta-core` APIs and map `TalibError` to `JsValue`.
5. Preserve `NaN` warm-up outputs so JS callers can use `Number.isNaN`.
6. Add host tests and `wasm-bindgen-test` when JS/WASM behavior matters.
</important>
